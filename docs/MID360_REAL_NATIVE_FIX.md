# MID-360 real hardware connection - native bridge fix

## What was wrong

The previous project contained a `native/build` directory generated by a non-Windows
CMake environment, but the .NET application expected:

- `LivoxHmiBridge.dll`
- and, indirectly, `livox_lidar_sdk_shared.dll`

The ZIP contained no Windows DLLs, so Windows reported:

`System.DllNotFoundException: Unable to load DLL 'LivoxHmiBridge' or one of its dependencies (0x8007007E)`

## Fix in this version

1. The vendor **Livox SDK2 source is unchanged**.
2. `LivoxHmiBridge` now links **livox_lidar_sdk_static**.
3. Therefore the runtime needs only `LivoxHmiBridge.dll` from our native layer.
4. The old `native/build` cache is removed. Windows gets a fresh `native/build-win-x64`.
5. The .NET project copies `LivoxHmiBridge.dll` into the application output and fails the build
   with a clear message if it is missing.

## Build on Windows / Visual Studio 2022

Open PowerShell in:

`LivoxHmi/scripts`

Run:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build_native.ps1 -Configuration Debug
```

Then open:

`LivoxHmiV1.sln`

Build `LivoxHmi.App` in **x64 / Debug**.

After the build, verify:

`src\LivoxHmi.App\bin\Debug\net8.0-windows\LivoxHmiBridge.dll`

exists beside `LivoxHmi.App.exe`.

For Release:

```powershell
.\build_native.ps1 -Configuration Release
```

and build the solution as x64 / Release.

## Important

Do not copy the old `native/build` directory back into this project.

Do not replace Livox SDK2 with another SDK.

The runtime chain is:

MID-360
 -> Livox SDK2 (vendor source)
 -> LivoxHmiBridge.dll
 -> LivoxHmi.Device
 -> PointCloudFrame
 -> 3D Viewer

Only after this native layer loads successfully should we troubleshoot IP/UDP/networking.
